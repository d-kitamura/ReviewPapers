# ReviewPapers 実装・運用引き継ぎ書

最終棚卸し日: 2026-09-01

対象バージョン: `0.1.0`

機能実装の基準コミット: `3527619 Initial implementation of ReviewPapers`

## 1. 目的と現在のスコープ

ReviewPapersは、学生の学会原稿や卒業論文をPDFのまま確認し、クリックした位置へ自由記述の
コメントを付けるデスクトップアプリである。発行時は、コメント一覧と番号ピン付きの元原稿を
結合した返却用PDFを生成する。

現在の製品方針は次のとおり。

- チェックリスト、採点、ルーブリック、年度、区分は扱わない。
- 選択フォルダ直下の複数PDFを切り替えて添削する。
- 同じ学生の別バージョンは、異なるPDFファイル名で別原稿として管理する。
- 元PDFは変更せず、コメントはJSON、返却物は別PDFとして保存する。
- コメントは通常テキストに加え、限定されたTeX数式を扱う。
- 返却PDFでは、数式表示とコピー用TeXソースを両方提供する。

## 2. 実行環境と依存関係

環境管理にはPixiを使用する。定義は `pixi.toml`、固定された解決結果は `pixi.lock` にある。

| 依存関係 | 用途 |
| --- | --- |
| Python 3.10以上 | アプリ本体 |
| Tkinter | デスクトップGUI。PixiのPython環境から利用する |
| PyMuPDF (`fitz`) 1.24以上、2未満 | PDF表示、座標、描画、結合、内部リンク |
| Pillow 10以上 | PDFページと数式プレビューの画像表示 |
| Tectonic 0.17系 | TeX数式の安全なコンパイル |

Pixiの対象プラットフォームは `win-64` と `linux-64`。主な開発・利用環境はWindowsで、
高DPI対応、Windows日本語フォント、エクスプローラー起動に対応している。Linuxでは返却フォルダを
`xdg-open` で開くが、日本語PDF出力に適したフォントが見つからない場合は追加対応が必要になる。

基本コマンド:

```powershell
pixi install
pixi run gui
pixi run test
pixi run make-fixtures
```

## 3. 利用方法

### 3.1 対象フォルダ

起動時に、添削対象PDFを直接置いたフォルダを選択する。

```text
{対象フォルダ}/
  山田太郎_卒業論文_v1.pdf
  山田太郎_卒業論文_v2.pdf
  鈴木花子_学会原稿.pdf
  review_results/              # コメントJSON。自動生成
  返却/                        # 返却PDF。自動生成
```

選択結果はリポジトリ直下の `.review_root` に保存される。環境変数
`PAPERS_REVIEW_ROOT` が有効なフォルダを指している場合は、そちらを優先する。

対象探索は再帰しない。フォルダ直下の `*.pdf` のみを起動時に読み込み、ファイル名のstemを
原稿ID・表示名として使う。添削開始後にファイル名を変更すると、従来のJSONと別原稿として扱われる。

### 3.2 コメント操作

1. 上部のコンボボックスで原稿を選ぶ。
2. PDF上をクリックしてコメント編集画面を開く。
3. コメントを入力し、「保存」または `Ctrl+Enter` で保存する。
4. PDFをドラッグするとスクロールになるため、ドラッグ後にはコメント画面を開かない。
5. 「コメント一覧表示」で既存コメントを確認し、行をダブルクリックして編集・削除する。

コメント編集画面はリサイズ可能で、入力欄とプレビュー欄の境界もドラッグできる。最後に閉じた
ダイアログサイズは、同じアプリ実行中の次回表示に引き継ぐ。

「align*挿入」は、現在のカーソル位置へ次の3行を挿入し、中央の空行へカーソルを移動する。

```tex
\begin{align*}

\end{align*}
```

### 3.3 発行と再発行

「添削結果PDF発行（未発行のみ）」は、`issued_at` が空、または `updated_at` より古いJSONだけを
対象にする。返却先は `返却/添削結果_{元PDFのstem}.pdf`。

出力PDFを削除しただけではJSONの発行状態は変わらない。数式レンダラーやPDFレイアウトの変更後に
再発行したい場合は、既存コメントを開いて内容を変えずに「保存」しても `updated_at` が更新され、
未発行状態になる。現時点では「全件を強制再発行」する専用ボタンはない。

## 4. ディレクトリとモジュール構成

| パス | 責務 |
| --- | --- |
| `review_app.py` | 起動、対象フォルダ選択、DPI設定、Tkメインループ |
| `packages/papers/paths.py` | 対象フォルダ、JSON保存先、返却先の解決 |
| `packages/papers/discovery.py` | フォルダ直下のPDF探索と原稿ID生成 |
| `packages/papers/domain.py` | 学生原稿向けの発行処理と返却フォルダ操作 |
| `packages/review/domain.py` | 汎用GUIと対象固有処理の境界 |
| `packages/review/app.py` | PDF表示、対象切替、ピン操作、コメント画面、非同期プレビュー |
| `packages/review/pdfview.py` | PDF描画とCanvas/PDF座標変換 |
| `packages/review/record.py` | コメントデータモデル、JSON永続化、発行状態、並び順 |
| `packages/review/texrender.py` | TeX解析、安全検査、Tectonic実行、数式キャッシュ |
| `packages/review/reportpdf.py` | コメントページ生成、元PDF結合、番号ピン、内部リンク |
| `fixtures/make_fixtures.py` | GUI動作確認用PDFの生成 |
| `tests/test_core.py` | 探索、JSON、TeX、PDF出力の回帰テスト |

依存の方向は概ね次のようになる。

```text
review_app.py
  -> PapersDomain
       -> discovery / paths
       -> ReviewDomain / record / reportpdf
  -> ReviewApp
       -> pdfview / record / texrender

reportpdf
  -> record / texrender / PyMuPDF
texrender
  -> Tectonic / PyMuPDF / Pillow
```

`ReviewApp` は汎用GUIで、学生原稿固有の保存先や発行操作は `PapersDomain` に閉じ込めている。
将来別の対象へ流用する場合は、原則として `ReviewDomain` を実装し、GUI本体へ条件分岐を増やさない。

## 5. データモデルと状態管理

コメントJSONはUTF-8で保存される。概念上の形式は次のとおり。

```json
{
  "target_id": "山田太郎_卒業論文_v2",
  "target_name": "山田太郎_卒業論文_v2",
  "pdf_relpath": "山田太郎_卒業論文_v2.pdf",
  "pdf_mtime": 0.0,
  "comments": [
    {
      "id": "UUID相当の32桁16進文字列",
      "page": 0,
      "pdf_x": 120.0,
      "pdf_y": 240.0,
      "text": "ここを修正してください。"
    }
  ],
  "updated_at": "2026-09-01T12:34:56",
  "issued_at": "2026-09-01T12:40:00"
}
```

- `page` は0始まり。UIと返却PDFでは1始まりで表示する。
- `pdf_x`, `pdf_y` はPDF上のポイント座標で、左上原点・Y軸下向き。
- JSON書き込みは `.tmp` へ出してから `os.replace` するため、通常の保存は原子的である。
- 保存のたびに `updated_at`、発行成功時に `issued_at` を秒精度で更新する。
- 未着手はJSONなし、未発行は `issued_at` なし、または `issued_at < updated_at`。
- 未知のJSONフィールドは読み込み時に無視する。将来の項目追加時も既存データを壊しにくい。

コメント番号は保存順ではなく、`page`、Y方向、X方向の読書順で毎回計算する。同じ行とみなす
Y座標の許容差は14ポイント。JSON内の `id` は編集対象の同一性を保つために使う。

## 6. GUIとスレッド設計

### 6.1 PDF表示と座標

PDF全ページをPyMuPDFで画像化して縦に並べ、Canvas幅へ自動フィットする。ウィンドウリサイズ後は
150ミリ秒のデバウンスを経て再描画する。Canvas座標とPDF座標はズーム倍率で相互変換する。

マウス押下後、移動量がDPI補正済みの4ピクセルを超えるとドラッグと判定する。ドラッグでなければ
クリック位置をPDF座標に変換してコメント画面を開く。元PDFの外部URIリンク上ではブラウザを開く。

### 6.2 数式プレビュー

入力変更から450ミリ秒後にプレビューを開始する。TeXコンパイルはデーモンスレッドで実行し、結果は
`queue.Queue` に入れる。Tkメインスレッドが `after(50, ...)` でqueueを読み、ウィジェットと
`PhotoImage` を更新する。

Tkinterはスレッドセーフではないため、ワーカースレッドから `root.after` やウィジェット操作を
直接呼ばないこと。`preview_revision` により、入力更新前の古いレンダリング結果は破棄する。

## 7. TeX数式処理

### 7.1 対応構文

- `$...$` のインライン数式
- `\begin{align}...\end{align}`
- `\begin{align*}...\end{align*}`
- 通常テキスト中の `\$` は文字 `$` として表示

`$$...$$`、数式環境の入れ子、未閉鎖の `$` / `align` は非対応。1つの数式は5000文字以内。

固定プリアンブル:

```tex
\documentclass[preview,border=2pt]{standalone}
\usepackage{amsmath}
\usepackage{amssymb}
\usepackage{bm}
\pagestyle{empty}
```

### 7.2 安全方針

Tectonicは `-X compile --untrusted` で実行する。さらに、ファイル入出力、パッケージ追加、
コマンド定義等に使える次の系統をパーサーで拒否する。

```text
documentclass, usepackage, input, include, includegraphics,
write18, write, openin, openout, read, catcode, csname,
newcommand, renewcommand, providecommand, def, gdef, edef, xdef,
let, futurelet, special, loop
```

この制限を緩める場合は、見た目の要望だけで判断せず、Tectonicの権限と入力境界を再評価する。

### 7.3 キャッシュ

数式ソースと `_RENDERER_VERSION` のSHA-256をキーに、1ページのベクトルPDFをキャッシュする。

- Windows: `%LOCALAPPDATA%\ReviewPapers\tex-cache`
- その他: `$XDG_CACHE_HOME/ReviewPapers/tex-cache` または `~/.cache/ReviewPapers/tex-cache`

コンパイルのタイムアウトは240秒。初回はTectonicのサポートファイル取得で時間がかかることがある。
プリアンブルやレンダリング結果へ影響する変更をした場合は `_RENDERER_VERSION` を更新し、古い
キャッシュと衝突しないようにする。キャッシュは派生物であり削除しても再生成できる。

## 8. 返却PDFの仕様

### 8.1 ページ構成

1. A4のコメント一覧ページ。収まらなければ「（続き）」ページを追加
2. 元原稿PDFの全ページ
3. 元原稿上へ黄色い番号ピンと双方向内部リンクを追加

日本語本文は、Windows上でメイリオ、游ゴシック等を順に探索して埋め込む。数式はTectonicが作った
PDFを `show_pdf_page` で配置するためベクトルのまま維持される。

### 8.2 数式とコピー用ソース

コメント本文は通常テキストと数式を組み合わせて配置する。表示数式は中央寄せ。各コメントに数式が
ある場合、その後に「TeXソース（コピー用）」とグレーのソース欄を置く。ソースはCourierでPDF上の
選択可能な文字として描画する。

パースまたはコンパイルに失敗してもPDF発行全体は止めず、原文とTeXエラーを表示する。

### 8.3 番号ピン

- PDF上の半径: 7ポイント
- 黄色背景の不透明度: 0.5
- 黒い輪郭と番号文字は不透明
- 番号はコメントの読書順と一致

元の文字を完全に覆わないことが製品要件である。透明度を変更する場合は、文字の可読性と番号の
視認性を両方、実際のPDFレンダリングで確認する。

### 8.4 内部リンク

コメント見出しと表示コメントをクリックすると、元原稿の番号ピンへ移動する。グレーのコピー用
TeXソース欄とそのラベルはリンク範囲から除外し、ドラッグ選択中の誤ジャンプを防いでいる。

番号ピンをクリックすると対応コメントへ戻る。移動先は対象の中心や文字ベースラインではなく、
描画物の上端と6ポイントの余白から計算する。

```text
コメント -> ピン: pin.pdf_y - PIN_RADIUS - LINK_VIEW_PADDING
ピン -> コメント: entry_top - FONT_SIZE - LINK_VIEW_PADDING
LINK_VIEW_PADDING = 6ポイント
```

ページ上端より小さくなる場合は `page.rect.y0` へ丸める。これは表示位置を試行錯誤する処理ではなく、
描画物の既知寸法に基づく計算である。PDFの拡大率はリンクの `zoom=0` により現在値を維持する。

## 9. 発行処理の流れ

```text
UIで「未発行のみ」を押す
  -> 全TargetのJSONを読む
  -> issued_atがない、またはupdated_atより古いものを抽出
  -> バックグラウンドスレッドで原稿ごとにPDF生成
  -> 成功したJSONだけmark_issued
  -> 失敗は原稿単位で記録し、残りを継続
  -> UIスレッドで一覧状態と完了ダイアログを更新
```

発行中にもう一度重い操作を開始しないよう、`ReviewApp.run_async` は同時に1ワーカーだけ許可する。

## 10. テストと確認手順

自動テスト:

```powershell
pixi run test
```

現在のテストは次を保証する。

- 同じ学生の別バージョンが別IDになる。
- JSONの保存・読み込み・発行状態が往復する。
- コメント番号がページ、Y、X順になる。
- インライン数式とalign/align*を分割し、TeXソースを保持する。
- 未閉鎖TeXと危険なコマンドを拒否する。
- Tectonicが `bm`、`mathbb`、alignを実際にコンパイルできる。
- 返却PDFにコメントページ、元原稿、双方向リンク、ベクトル数式がある。
- TeXソースが抽出可能な文字として残る。
- グレーのソース欄とリンク矩形が交差しない。
- 番号ピン背景の不透明度が0.5である。
- リンク先が描画物の上端から6ポイント上になる。

PDF生成を変更した場合は自動テストだけで終えず、次も確認する。

1. 返却PDFをPyMuPDFで再度開き、ページ数、`get_links()`、`get_drawings()`、文字抽出を検査する。
2. 全ページをPoppler等でPNGへ変換する。
3. 日本語、改行、数式、ソース欄、ページ送り、番号ピン、リンク位置を目視する。
4. Acrobatまたは実際に利用するビューアで、リンク移動とTeXソースのドラッグ選択を操作する。

GUIの変更では、少なくとも以下を手動確認する。

- 複数PDFの切替
- クリックとドラッグの区別
- コメント新規作成、編集、削除、`Ctrl+Enter`
- ウィンドウと上下ペインのリサイズ
- `align*挿入` の挿入文字列とカーソル位置
- 入力中にUIが固まらず、古いプレビューが混ざらないこと

## 11. 現在の制約と注意点

- 対象PDF一覧は起動時にだけ読み込む。起動後に追加したPDFを反映するには再起動が必要。
- PDF探索はサブフォルダを再帰しない。
- PDF名の変更は原稿ID変更になる。既存JSONの自動移行機能はない。
- 同じファイル名のPDFを別内容へ差し替えても、保存済み座標を自動補正しない。
- `pdf_mtime` は記録するが、現時点では原稿差し替え検出や発行判定に使っていない。
- 「全件強制再発行」は未実装。出力PDFの削除だけでは再発行対象にならない。
- TeXマクロのユーザー定義、図、表、任意パッケージ、`$$...$$` は非対応。
- 長いTeXソースはPDF上で固定文字数ごとに折り返すため、コピー時に改行が含まれる可能性がある。
- Linuxの日本語フォント選択は未整備。
- リポジトリには現時点で `LICENSE` ファイルがない。外部公開・配布前に、元にしたプロジェクトの
  ライセンス条件を確認し、必要なライセンスと帰属表示を整備する。

## 12. ここまでの変更履歴

元のReviewPDFを参考に、ReviewPapersでは次の方向へ整理した。

1. チェックリスト、年度、区分を削除し、フォルダ直下のPDFだけを対象にした。
2. 複数学生・複数バージョンをファイル名単位で切り替えられるようにした。
3. コメント編集ウィンドウと入力領域をリサイズ可能にした。
4. TeXソース入力と非同期数式プレビューを追加した。
5. `$...$`、align、align*、`bm`、`amsmath`、`amssymb` に対応した。
6. PDFへベクトル数式とコピー用TeXソースを併記した。
7. `align*挿入` ボタンを追加した。
8. 番号ピンを半透明化した。
9. コピー用TeXソース欄を内部リンクのクリック範囲から除外した。
10. 双方向リンクの移動先を描画物上端より6ポイント上へ調整した。

## 13. 次のCoding AIへのチェックリスト

作業開始時:

- `git status` と最新コミットを確認する。
- `README.md`、本書、`AGENTS.md`、関連テストを読む。
- `.review_root` が指す実レビュー環境をテストで変更しない。
- 変更対象の責務が `ReviewApp`、`PapersDomain`、`record`、`texrender`、`reportpdf` のどこかを決める。

作業完了時:

- `pixi run test` を実行する。
- GUIまたは生成PDFを変更した場合は実物を操作・目視する。
- JSON互換性、TeXソース保持、元PDF非変更、リンク範囲を再確認する。
- 生成物や個人データがGitに入っていないことを確認する。
- ユーザーの明示指示なしにコミット・プッシュしない。
